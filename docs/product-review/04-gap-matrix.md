## 分类清单

**🟢 已领先（保持并放大）**：撞单保护、AI 成本审计、状态机严谨性、（相对 AI 层厂商的）一体化人工工作台。

**🔵 达标（维持）**：多租户隔离、幂等、AI→人工三触发交接、注入清洗、凭据加密。

**🟡 落后（追平）**：收件箱运营性、AI 回复深度、知识库、报表、移动端。

**🔴 完全缺少（按 P0→P2 补）**：出站投递、客户 360°、通知、SLA、分配、宏、协作、自动化引擎、CSAT、QA/Coaching、行动执行、集成生态。

**⚫ 建议删除/合并/重设计**：
1. 模型下拉里的 `gemini-2.5-pro` 假选项 → 删（或真做多 provider）。
2. 监控页硬编码「并发 24」装饰数据 → 删。
3. 前端硬编码三层单价 → 改从 API 读取 env 配置。
4. WhatsApp stub 渠道显示 → 隐藏到"即将支持"，不占"未接入"位造成期望落差。
5. 「AI 处理中」状态下客服必须先手动转人工才能说话 → 合并为"直接回复即接管"（一次点击变零点击，状态机已支持 claim 语义）。
6. seed 的"历史工单"与真实工单同池 → 隔离为 demo 租户，避免污染任何演示/运营视图。

**最值得优先开发的差异化（详见交付物 5/6）**：
1. **透明 AI 成本中心**（routing_logs 已是半成品，直击 Intercom 最大差评）。
2. **零割裂 AI↔人工同台**（打 Sierra/Decagon/Ada 无人工工作台的结构软肋）。
3. **严格口径的 per-resolution 计费与审计**（"客户确认+7 天不重开"）。
4. **游戏行业纵深**（玩家档案/充值/公会上下文的 vertical AI 客服——通用巨头不会为此定制）。
