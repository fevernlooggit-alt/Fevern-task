# 交付物 5 — 最终版 AI CRM 产品架构（"最方便的最终产品"设计）

> 从零重想：如果今天重新发明这个产品，它应该怎么运作。原则——每个 AI 功能必须回答
> "解决什么问题 / 谁在用 / 怎么操作 / 值多少钱"，否则不做。

## 0. 产品主张（一句话）

**「一个收件箱、一个客户真相、一个可审计的 AI 同事」**——
AI 处理它有把握的一切，人处理例外；两者在同一张工单、同一份上下文里无缝换手，
每一次 AI 行为都有来源、成本和理由可查。

## 1. 信息架构（目标态五区）

```
┌─ 收件箱（唯一工作面）──────────────────────────────────────────────┐
│ 左：队列/视图（我的/未分配/SLA 风险/VIP…可保存筛选，键盘导航）        │
│ 中：会话流（全渠道消息+内部备注+AI 事件内联）+ 快捷回复 + AI 起草     │
│ 右：客户上下文栏（档案/历史工单/订单充值/情绪/流失风险/建议动作）      │
├─ 主管驾驶舱：实时队列健康、SLA 风险、坐席负载、异常告警、AI 日报       │
├─ AI 工作室：EVA 配置、知识库+缺口清单、SOP/Playbook、仿真回放、发布    │
├─ 洞察：解决率/成本中心/CSAT/QA 评分/知识飞轮指标，全部可下钻导出       │
└─ 设置：渠道接入向导、用户与团队、SLA 策略、自动化规则、API/webhook、审计 │
```

关键差异 vs 现状：客户上下文栏（现在完全没有）、主管驾驶舱（现在只有 4 张卡）、
AI 工作室把"配置-知识-测试-发布"闭环（现在只有裸配置）、设置区（现在不存在）。

## 2. 十项"最方便"原则 → 具体设计

| # | 原则 | 具体设计（现状差距） |
|---|---|---|
| 1 | 新用户零培训上手 | 渠道接入向导（贴 bot token → 自动 setWebhook → 发测试消息验证）；空状态引导；演示租户隔离。现状：接渠道要直接 POST API 塞加密 JSON |
| 2 | 减少页面切换/重复输入 | 客户上下文栏钉在工单右侧（不跳页）；键盘优先（j/k 换单、r 回复、e 解决）；宏+变量。现状：查客户信息无处可查 |
| 3 | AI 主动分类/总结/回复/分配/跟进 | 见 §3 能力清单。核心：AI 打意图/情绪标→路由→起草→客服一键发送 |
| 4 | 一页看全客户 | 客户 360°：跨渠道身份合并（email/telegramId 既有字段）、历史工单、订单/充值（游戏后台 API）、行为时间线 |
| 5 | 管理层快速看团队/问题/风险 | 主管驾驶舱 + AI 日报（今天 N 单、异常 X、SLA 风险 Y、建议 Z）推送到邮箱/IM |
| 6 | 系统主动发现异常/投诉/流失/机会 | 情绪骤降告警、同类问题突增聚类（"过去 1 小时 14 单提到充值失败"→ 疑似事故）、高价值客户负面情绪即时升级 |
| 7 | AI 自动执行但可审可控 | 三档权限：自动执行（查订单）/需审批（补发奖励）/禁止（退款）；全部进审计流水含输入输出与依据 |
| 8 | 所有渠道一个 Inbox | 已有骨架，补出站+渠道扩展；同客户跨渠道自动并线 |
| 9 | 后台设置无需技术人员 | 一切 env-only 配置（成本单价/锁 TTL/关键词）搬进设置 UI；规则引擎用"当…如果…就…"三段式 |
| 10 | 每项 AI 功能可算账 | 成本中心：每层每渠道每租户的调用量/成本/解决率/被采纳率；"这个月 EVA 替你省了 N 小时人工" |

## 3. AI 能力设计（16 项审查，含否决项）

每项按【问题→用户→操作→价值→依据】给出。标 ⛔ 的是评估后**不建议做**或降级的。

1. **意图+情绪识别**：入站消息自动打意图标（充值/账号/Bug/投诉）与情绪分。客服看列表即知轻重；路由和报表的地基。操作：全自动，标签可人工纠正（纠正即训练数据）。价值：分诊时间→0，为 SLA/路由/异常检测供数。
2. **回复生成+来源引用**：EVA/客服起草的每句答案标注引用的 KB 条目/标签答案，客服悬停可见原文。解决"AI 说的对不对我不敢发"的信任问题。价值：客服采纳率是可量化 KPI；也是企业客户安全审查的敲门砖。
3. **客户历史自动摘要**：打开工单时右栏 3 行摘要（老玩家/月充 $200/上周投诉过提现慢）。替代人肉翻历史。注意：**摘要必须缓存**且标注生成时间，不是每次全量重算（成本）。
4. **AI 分配**：按意图×技能×负载×历史 CSAT 推荐处理人；先"推荐"后"自动"，主管可改。前提是先有基本分配机制（现在连手动指派都没有——先走 P1 的轮询，AI 版本 P2）。
5. **AI 建单/更新**（渠道消息→自动建单已有 ✅）：升级为自动填意图/优先级/标签；解决后自动归档摘要进客户时间线。
6. **建议下一步行动**：交接摘要末尾附具体动作（"让用户提供订单号→查支付网关→如 pending>24h 走补单 SOP"），点击即执行对应工具。这是把 SOP 编排（行业收敛点）落到交接场景的切口。
7. **主动跟进提醒**：等待客户回复超时自动提醒/代发跟进；done 前自动问"还有其他问题吗"。补上"人会忘"的洞。
8. **高价值/流失风险识别**：充值档位+近期情绪+投诉频率→风险分；驾驶舱专列。游戏场景直接对应收入保护。
9. **主管日报/周报/异常报告**：自然语言日报自动生成推送。替代人肉拉数。必须每条结论可点开看底层数据（反幻觉设计）。
10. **AI QA**：全量会话按合规/准确/语气打分，低分进人工复核队列。中端市场空白（只有 Zendesk 有且 $35/席）。P2。
11. **AI Coaching**：基于 QA 结果按人出改进卡片。依赖 10 先行。P2-P3。
12. ⛔→P3 **AI 自动建 Workflow**：Decagon AOP 方向正确，但我们连规则引擎都没有。先做"10 个预置规则+手动配置"（P1），NL 生成是 P3。为看起来先进而先做 NL 版是本末倒置。
13. **知识缺口发现**：每次 handoff/低置信度按主题聚类→"本周 23 单问合服补偿，KB 无此文章"→ 一键从工单生成草稿→admin 审批发布。解决率的复利飞轮，Zendesk Knowledge Builder 同款。P2 头部。
14. **跨系统行动执行**：查订单/补发/封禁申诉等真实动作，走 §2-7 三档权限+全审计。这是从"会聊天"到"能干活"的分水岭，也是 per-resolution 收费的前提。P2。
15. **多语言实时翻译**：玩家马来语进→客服中文看/中文回→玩家马来语收。东南亚游戏场景刚需（zh/en/ms 检测已有）。P2。
16. **AI 可追踪性**：每次 AI 行为记录输入/输出/模型/成本/依据（routing_logs 扩展）。**这不是功能是地基**，所有 1-15 都必须写入。已领先半步，做完整个就是"可审计 AI"卖点。

⛔ **明确不做清单**：通用销售 Pipeline（场景外，见交付物 6）；AI 语音客服（P3 之后再评估，资本热但我们渠道未稳）；开放式"AI 自动改配置"（治理噩梦）。

## 4. 目标技术架构（演进式，不推倒重来）

```
现有保留：Fastify+Prisma 单体、状态机、锁、routing_logs、多租户模型 ✅
新增层：
 1. Outbound Delivery（渠道适配器接口 + BullMQ 重试队列 + 投递状态）← 第一优先
 2. Retrieval（pgvector 语义检索，替换 contains；文章引用 ID 贯穿到消息 meta）
 3. Action Framework（工具注册表 + 权限档位 + 审批队列 + 执行审计）
 4. Rules Engine（触发-条件-动作，先 10 个预置模板）
 5. Insight Pipeline（意图/情绪打标 → 聚合物化视图 → 驾驶舱/日报）
前端：引入 URL 路由（/inbox/:ticketId 等）→ 客户上下文栏 → 驾驶舱 → 设置区
```

## 5. 商业模式建议（呼应竞品结论）

- 座席费定价锚 Freshdesk/Zoho 区间（进入门槛），AI 按 **严格口径 resolution**（客户确认或 7 天不重开且未转人工）计费，全量审计可查——把 Intercom 的"assumed resolution"争议做成我们的信任卖点。
- routing_logs 成本中心免费开放：让客户看见每一分 AI 钱花在哪，行业没人敢这么透明。
- 垂直纵深（游戏/虚拟商品）做默认模板：玩家档案字段、充值查询 action、合服/活动公告知识包。
