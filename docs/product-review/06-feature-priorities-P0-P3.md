# 交付物 6 — 最终产品功能清单（P0–P3 完整优先级）

> P0 = 正式推出前必须具备；P1 = 形成市场竞争力；P2 = 形成明显差异化；P3 = 长期领先。
> 每项字段：角色 / 场景 / 当前状态 / 问题 / 建议设计 / 操作流程 / AI 参与 / 后台配置 / 验收标准 / 难度 / 商业价值。

---

## P0 — 正式推出前必须具备（否则不可售卖）

### P0-1 出站消息投递（修复 B-00）
- **角色**：终端客户（受益）、全体（依赖）。**场景**：客户在 Telegram/网页问问题，EVA 或客服回复后客户能收到。
- **当前**：回复只写 DB+内部 WS；**问题**：对话单向，产品闭环不存在。
- **设计**：`OutboundAdapter` 接口（telegram/livechat/email 三实现）+ BullMQ 投递队列（重试/退避/死信）+ 消息 `delivery_status`（pending/sent/failed）展示在气泡角标；LiveChat widget 升级为轮询或 WS 接收。
- **流程**：客服点发送 → 气泡出现"投递中"→ 变"已送达/失败可重试"。**AI 参与**：EVA 回复走同一队列。
- **配置**：渠道凭据（已加密存储）；重试策略 env。**验收**：Telegram 真机收到 EVA 与人工回复；投递失败在 UI 可见并可手动重试；断网重启不丢消息。
- **难度**：中 · **价值**：★★★★★（存在前提）

### P0-2 收件箱可运营化（修复 B-01/B-03/B-20）
- **角色**：agent/主管。**场景**：500 张工单的真实负载下找到该处理的单。
- **当前**：closed 刷屏、无分页、默认选中空单。
- **设计**：默认视图排除 closed；排序改"活跃状态优先+最后客户消息时间"；cron 关单不触碰排序字段（或用独立 `sorted_at`）；无限滚动分页；「已关闭」独立筛选；默认选中第一张**活跃**单。
- **验收**：cron 运行后首屏仍为活跃单；135 张单可全部滚动触达；筛选各状态计数与 DB 一致。
- **难度**：低 · **价值**：★★★★★

### P0-3 客户上下文栏 + 客户档案（最小 360°）
- **角色**：agent。**场景**：回复前 3 秒了解"这是谁、来过几次、上次为什么来"。
- **当前**：end_users 有数据无任何 UI（B-23）。
- **设计**：工单右侧栏：客户名/渠道身份/首次来访/历史工单列表（点击跳转）；同 email/telegramId 自动并线提示。
- **AI 参与**：P1 阶段叠加 AI 摘要（见 P1-6）。**配置**：无。
- **验收**：同一客户第二张工单能在右栏看到第一张；跨渠道同 email 客户显示合并建议。
- **难度**：中 · **价值**：★★★★★

### P0-4 通知系统（修复 B-21）
- **角色**：agent/主管。**场景**：不盯屏也不漏 handoff。
- **设计**：浏览器 Notification+声音（新 handoff/被指派/客户回复我锁定的单）；主管：SLA 风险通知；每人可开关。
- **验收**：后台标签页也能收到新 handoff 通知；免打扰开关生效。
- **难度**：低 · **价值**：★★★★

### P0-5 用户与团队管理 + 安全基线（修复 B-15）
- **角色**：tenant_admin/super_admin。**场景**：新客服入职 5 分钟内开好号。
- **设计**：用户 CRUD UI（邀请邮件/停用/改角色）、修改密码、重置流程、登录速率限制（IP+账号）、会话管理；审计登录事件。
- **验收**：全流程不碰 DB 完成开号停号；连续 5 次错密码触发限速 429。
- **难度**：中 · **价值**：★★★★（企业采购门槛）

### P0-6 前端权限一致性 + KB 阅读视图（修复 B-07/B-08）
- **设计**：按角色收敛可操作控件；KB 卡片对所有角色展开只读全文（admin 另有编辑钮）；客服可在回复框旁搜索并引用 KB。
- **验收**：viewer 全站无可点写操作；agent 能读 KB 全文并一键插入摘录。
- **难度**：低 · **价值**：★★★★

### P0-7 URL 路由与深链（修复 B-06）
- **设计**：react-router：/inbox/:ticketId、/eva、/kb/:id、/monitor、/settings/*；刷新保位；工单链接可分享。
- **验收**：刷新任意页面停留原地；粘贴工单 URL 直达该单。
- **难度**：低 · **价值**：★★★

### P0-8 AI/渠道健康状态真实化（修复 B-04/B-13/B-14）
- **设计**：eva-config API 返回每层 `available`+原因（缺 key/连通失败），UI 开关旁显示真实状态；渠道显示最近入站/出站时间与错误；删除假模型选项与硬编码单价/并发数（改从 API 读取）。
- **验收**：不配 key 时 L3 显示"未配置凭据"；env 改单价 UI 同步；下拉无不可用模型。
- **难度**：低 · **价值**：★★★★（信任）

### P0-9 危险操作确认 + 输入法保护（修复 B-11/B-10）
- **设计**：删除二次确认+软删除（deleted_at）；compose Enter 发送检查 `isComposing`，Shift+Enter 换行。
- **验收**：中文输入法组词按 Enter 不发送；删除可在 30 天内恢复。
- **难度**：低 · **价值**：★★★

### P0-10 上手体验（修复 B-17 + 原则 1）
- **设计**：README/部署脚本修正（postinstall prisma generate、e2e 环境变量文档）；渠道接入向导（Telegram：贴 token→自动 setWebhook→收发测试）；demo 数据隔离到演示租户。
- **验收**：新工程师按 README 一次跑通；非技术管理员 10 分钟内接通一个 Telegram bot 并完成首次 AI 问答闭环。
- **难度**：中 · **价值**：★★★★（实施周期即隐形定价）

## P1 — 形成市场竞争力（追平行业标准）

### P1-1 SLA 策略与升级
角色：主管/admin。设计：按优先级×渠道定义首响/解决时限；工单列表倒计时列；临期通知、违约自动升级（提优先级/通知主管）。AI：按意图预测应设优先级。配置：SLA 策略表 UI。验收：临期 15 分钟通知；违约记录进报表。难度：中 · 价值：★★★★★（B2B 采购硬门槛）

### P1-2 分配与路由（先手动+轮询）
角色：主管/agent。设计：手动"指派给…"、"转交给…"（带留言）；未分配队列轮询/最少负载自动派。AI：P2 升级技能路由。验收：指派触发通知；轮询分布均匀（±1）。难度：中 · 价值：★★★★

### P1-3 快捷回复（人工侧宏）+ AI 起草
角色：agent。设计：/ 唤出宏面板（变量：客户名/工单号）；「AI 起草」按钮基于 KB+上下文生成草稿（引用来源标注），客服编辑后发送；记录采纳率。配置：宏 CRUD（admin）。验收：宏插入<2 秒；AI 草稿带≥1 条来源引用；采纳率进报表。难度：中 · 价值：★★★★★

### P1-4 内部备注 + @提及
角色：agent。设计：compose 切换"回复客户/内部备注"两模式（Cmd+Shift+N）；@同事触发通知。验收：内部备注绝不出站（复用既有 internal 隐藏机制，已有测试）；@人收到通知。难度：低 · 价值：★★★

### P1-5 意图与情绪自动打标
角色：系统/全体。设计：入站消息过分类器（L2/L3 或独立轻模型）；标签显示在列表与详情，可人工纠正；供路由/报表/异常检测消费。配置：意图类目管理 UI。验收：标注准确率抽检≥85%；纠正落库。难度：中 · 价值：★★★★（多项 AI 能力的地基）

### P1-6 真·AI 交接摘要 + 客户历史摘要（修复 B-19）
设计：handoff 时 LLM 生成真实摘要（诉求/已试/卡点/建议下一步）；客户上下文栏 3 行历史摘要（缓存+时间戳）。验收：摘要事实性抽检；生成失败降级为现模板。难度：中 · 价值：★★★★

### P1-7 CSAT 采集
设计：resolve 后经出站渠道自动发满意度（1-5 + 评语）；进工单/客服/租户三级报表；差评自动建跟进任务。依赖 P0-1。验收：回收率、差评告警可用。难度：低 · 价值：★★★★

### P1-8 成本中心看板（放大既有优势）
设计：routing_logs 聚合：层级/渠道/租户维度调用量、成本、命中率趋势；预算阈值告警；"AI 本月节省 N 人时"估算。验收：数字与 routing_logs 逐条可对账。难度：低 · 价值：★★★★（差异化卖点提前落地）

### P1-9 规则引擎 v1（10 个预置模板）
设计：触发（新单/超时/关键词/情绪）×条件×动作（改优先级/指派/通知/自动回复）三段式 UI；先只开放预置模板参数化。验收：规则命中有审计；关闭即停。难度：高 · 价值：★★★★★

### P1-10 API key + 出站 Webhook + 公开 API 文档
设计：租户级 PAT（可撤销、scope）；ticket.created/updated、message.created 出站 webhook（签名+重试）；OpenAPI 文档站。验收：第三方用 PAT 完成建单-回复闭环。难度：中 · 价值：★★★

### P1-11 Email 渠道真实接通
设计：IMAP 轮询/SMTP 出站（worker seam 已留）；邮件↔工单线程映射。验收：外部邮箱来回各一封成单成回。难度：中 · 价值：★★★★

## P2 — 形成明显差异化

### P2-1 AI 行动执行框架（Action Framework）
角色：EVA/agent/admin。场景：玩家问"充值没到账"→ EVA 直接查支付网关给结论。设计：工具注册表（HTTP 模板+参数 schema）；三档权限（自动/需审批/禁止）；审批队列 UI；全审计（输入/输出/依据/操作者）。AI：EVA 在回复中调用工具并引用结果。验收：查询类零人工完成；补发类走审批留痕。难度：高 · 价值：★★★★★（从会聊到能干活的分水岭，per-resolution 计费前提）

### P2-2 语义检索 + 来源引用（RAG 升级）
设计：pgvector 向量化 KB；EVA 回复 meta 记录引用文章 ID；UI 气泡可展开来源。验收：改写问法仍命中；每条 L2/L3 回复≥1 引用或明确"无依据转人工"。难度：中 · 价值：★★★★

### P2-3 知识飞轮（缺口发现→草稿→审批）
设计：handoff/低置信度按意图聚类周报"Top 缺口"；一键从工单生成文章草稿（pending_confirmation 复用既有状态）；admin 审批后 synced 进检索。验收：缺口→发布→该意图解决率提升可量化。难度：中 · 价值：★★★★

### P2-4 主管驾驶舱 + AI 日报/异常报告
设计：实时队列健康/坐席负载/SLA 风险/情绪异常聚类（"1 小时内 14 单提充值失败"）；每日自然语言日报推送（每条结论可下钻到底层单据）。验收：注入模拟事故 30 分钟内出现聚类告警。难度：高 · 价值：★★★★

### P2-5 AI QA + Coaching v1
设计：全量会话按准确/合规/语气评分；低分进复核队列；按客服聚合出改进卡片。验收：评分与人工抽检一致性≥80%。难度：高 · 价值：★★★★（中端市场空白）

### P2-6 流失风险与高价值客户识别
设计：充值档位（游戏后台 API）+情绪趋势+投诉频率→风险分；驾驶舱 VIP/风险专列；负面情绪 VIP 自动升级优先级。验收：风险名单周更、可导出、命中复盘。难度：中 · 价值：★★★★

### P2-7 多语言实时翻译
设计：入站检测（已有 zh/en/ms）→ 客服视图双语对照 → 出站回translate 客户语言；翻译调用进成本中心。验收：ms 客户全程母语交互，客服全程中文。难度：中 · 价值：★★★（东南亚游戏刚需）

### P2-8 客户标签/分群 + 跟进任务
设计：客户标签 CRUD+保存筛选（轻量 Segment）；工单/客户上挂跟进任务（到期通知）；AI 建议跟进（超时未回自动提醒）。验收：分群可作规则引擎条件。难度：低-中 · 价值：★★★

### P2-9 WhatsApp / Discord 渠道
设计：复用 OutboundAdapter + webhook ingest 模式接 WhatsApp Business API 与 Discord bot。验收：双渠道收发闭环。难度：中 · 价值：★★★
